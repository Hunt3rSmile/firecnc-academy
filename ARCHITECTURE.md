# Архитектура

Один desktop, один независимый будущий сервер активации. npm workspaces, один package-lock. Никаких HTTP-сервисов для локального обучения.

| Компонент | Ответственность | Зависимости среды |
|---|---|---|
| cnc-core | Лексер с исходным написанием, модальные группы, атомарный кадр, координаты, линейная/круговая геометрия | Стандартный JS; без DOM, Electron, React, файлов и сети |
| simulation | Занятость r/Z, высоты XY, формы инструментов, дискретные столкновения, измерения | Только core; TypedArray |
| learning | Проверяемый контент, вопросы, оценивание по контрольным сечениям | Zod, simulation; без внешнего кода из контента |
| contracts | Типизированные сообщения, схемы IPC/проектов, единая матрица модулей | Zod, type-only core/simulation |
| licensing | Ограниченный FCNC1/JSON, Ed25519 verify, ID ключа/установки | Node crypto, contracts, Zod; только доверенный процесс |
| license-issuer | Генерация и подпись, интерактивный PKCS#8, журнал выпуска | Отдельный CLI, файловая система; отсутствует в клиентском bundle |
| desktop | Данные, диалоги, файловые лимиты, импорт лицензии и права на действия | Electron main, better-sqlite3 |
| ui | React, Monaco, 2D Canvas, Three.js, Worker и управление воспроизведением | Sandbox renderer; ограниченный contextBridge |

Поток: текст → токены → проверка кадра → новый modal state → MachineEvent → проверка движения/материала → результат → визуализация. Three.js не участвует в вычислении результата. Worker получает ограниченный проект и число кадров, сообщает прогресс не чаще десяти долей полного расчёта. Отмена завершает Worker; срок расчёта UI ограничен 30 с. Сегменты/вычисления ограничены также внутри ядра. Результат не зависит от скорости проигрывания.

Для отката кадра заново создаётся материал и детерминированно воспроизводится префикс событий. При аварии снимок начала текущего кадра восстанавливает материал и modal state вместе. M0 останавливает пошаговое воспроизведение; «Рассчитать» проверяет все кадры, включая участки после учебной остановки.

`firecnc://app/` — локальная secure standard scheme. Протокол разрешает только GET внутри dist/ui. CSP запрещает произвольные script, connect, object. Inline style разрешён для React/Monaco; inline script и eval запрещены. NodeIntegration=false, contextIsolation=true, sandbox=true. Навигация и новые окна заблокированы; разрешения браузера отклоняются. Preload не предоставляет произвольный invoke или путь к файлам. Каждый IPC проверяет mainFrame, sender, URL, схему, размер и необходимые модули.

Физика рассчитывается в renderer Worker после проверки права в main. Это лицензирование учебных функций, не защита от переписывания приложения администратором ОС. Лицензируемые записи и разрешение запуска проверяются в main заново; состояние React не является источником прав.

SQLite schema v1: profiles, progress, attempts, projects, settings. Миграция выполняется транзакционно; перед преобразованием существующей БД v0 создаётся Backup API-копия. Более новая версия отклоняется. Вопросы каждой попытки сохраняются целиком вместе с версией и ответами. Банк после обновления не переписывает разбор прошлой попытки. Полноценные сущности ExamAttempt с таймером, QuestionRevision, преподаватель и audit ещё предстоят.

Проект v1 фиксирует тип станка, программу, G54, шаг сетки и имя. Заготовки/инструменты пока определены версией учебного сценария и не настраиваются; следующий формат должен сохранять их явные версии и геометрию. Изменение этих значений требует миграции проекта, а не тихой смены смысла v1.

Системный Node и Node Electron не взаимозаменяемы. postinstall явно загружает Electron и вызывает electron-rebuild. Нативный SQLite пакуется asarUnpack `**/*.node`; Linux E2E запускает его внутри реального Electron. Вызов SQLite из host Node после такой пересборки не является способом проверить Electron ABI.
