## Рабочая версия 0.3.0

Strict typecheck — без ошибок. **189 Vitest**, **15/15 Electron E2E** на Linux. Последний полный прогон: `.local/e2e-acceptance-0.3.log`; скриншоты, PDF и следы сбоев — `test-results/` (не публикуются как пользовательские данные). Независимые тесты KDF сравнивают scrypt с вектором Python hashlib.

Vitest проверяет координаты/G54/диаметральное X, 100 мм/F100 = 60 с, дуги в обеих плоскостях и обоих направлениях I/J/K и ±R, атомарный отказ, модальные конфликты/неподдерживаемые слова/лимиты. M2/M30 выключают шпиндель/СОЖ, M0 сохраняет режимы. Для всех 20 заданий эталон проходит реальный симулятор и аналитику полной формы. Измерения/объёмы дополнительно сравниваются с кольцом, цилиндром, прямоугольником и капсулой; внутренний дефект не засчитывается при правильных наружных пробах. Проверяются патрон/тиски/держатель/G0/выключенный шпиндель/направление/пределы, длинный ход через препятствие, откат материала, другой G54, небезопасная геометрия крепления, незавершённый исходник и неподходящий инструмент. Глубокий боковой проход фрезы не удаляет несрезанную крышку.

Банк: 24 урока, 120 разных формулировок, устойчивые ID/связи/диапазоны и восемь типов вопросов. Целочисленная модель приборов проверена на нуле, переходах и краях; штангенциркуль проверен по всему диапазону нониуса. Экзамен сохраняет снимок, seed/порядок, ответы, подсказки, абсолютный дедлайн; истечение/откат часов и обновление банка не меняют прошлый разбор.

Ed25519: подмена payload/подписи, product/key/kind/version/modules, даты/привязка, строгий JSON/дубликаты/размеры, публичный вектор, зашифрованный PKCS#8. Owner CLI keygen → issue Teacher → verify проверялся отдельно; пароль PKCS#8 вводился без эха. Ключи `.local` и публичного вектора не считаются доверенными в release.

Сервер: настоящие параллельные HTTP-запросы при одном месте дают ровно одну активацию. Проверены идемпотентность и потеря ответа, хеши вместо исходных секретов, невозможность renew/deactivate по одному ID, граница основной лицензии/lease, отзыв, деактивация/сброс с удержанием места до expiresAt, административная аутентификация, дубликаты JSON и rate limit. Повреждённый ответ/отключённый сервер не заменяет действующий клиентский токен.

Playwright `_electron`, sandbox включён, отдельные временные каталоги данных:

1. Онлайн Lab: ключ → подписанный lease → перезапуск с выключенным сервером → реальное Ø30 offline → срок истёк → JSON-экспорт работает.
2. G90/G91: ввод с запятой, сохранение режима/точки/ответа после перезапуска и полный разбор.
3. 3D: угол настоящего ротора меняется при M3, фиксируется на паузе, M5 останавливает.
4. Урок → отметка → тест/разбор → закрытие → сохранённый профиль/прогресс; офлайн-лицензия/подделка/модули; материал обоих станков.
5. Экзамен с восемью типами: UI-ввод, автосохранение, перезапуск, точный состав, 15/15, разбор и PDF после истечения лицензии.
6. Дедлайн экзамена истёк: ответы сохраняются, продолжение запрещено, разбор открывается.
7. Измерения: объяснение, модульная блокировка, серия без преждевременной подсказки, запятая и восстановление.
8. Практика: Node Worker повторно считает, сохраняет полную геометрию/исходник/версию/оценку; разбор после перезапуска.
9. Backup живой WAL-БД, quick_check, запуск на отдельной восстановленной копии; миграция v0→v6 сохраняет контрольную запись и создаёт before-migration копию.
10. Преподаватель: пароль, вопрос/тест/задание, импорт/экспорт, повреждённый пакет без потери данных, редакция/снимок, другой профиль и ограничения Student.
11. Обновления: безопасный ответ GitHub Releases, новая версия/ссылка/настройка после перезапуска, без фиктивного опубликованного релиза.
12. Monaco/IPC, авария/ошибка, 2D, откат заготовки и следующий кадр, экспорт, узкие экраны.
13. Мастерская: узлы, разборка/виды, неверные зажим/ноль/вращение, восстановленный шаг, передача проекта в симулятор и Ø30.
14. CAD/CAM: рисование/точные размеры/дуга, запрет неподдержанного профиля без потери чертежа, сохранение/перезапуск, обработка Ø32, карман и экспорт после истечения лицензии. Дополнительно проверяется настоящая отмена Node Worker из интерфейса.
15. Восстановление через UI: повреждённый файл не меняет данные, правильная копия создаёт защитный снимок, заменяет БД и после перезапуска возвращает прежний прогресс. В unit-тестах проверяются повреждённые JSON-записи и неожиданные таблицы/триггеры.

PDF: 15 вопросов, 5 страниц A4, кириллица и переносы визуально просмотрены на всех страницах через Poppler. Дополнительно получен настоящий PDF из Windows CI (157615 байт, A4, без JavaScript), отрендерены и просмотрены все пять страниц — перекрытий/обрезания нет. Скриптов/внешних assets в отчёте нет. Визуально проверены главная, урок, материал обоих станков, ошибка/авария, активная/неактивная лицензия, координаты, приборы, экзамен. Также просмотрены CAD/CAM с проверенным токарным профилем и карманом, наладка и преподаватель. Автоматический успех не заменяет ручную приёмку всех сочетаний экранов.

Viewport 1366×768, 1093×614 и 911×512 проверяются на overflow/переключение вкладок. Последние два моделируют доступную площадь при увеличении масштаба и **не заменяют Windows DPI 125/150%**.
