# Реально выполненные проверки

Дата: 14 ноября 2026. Linux x64, Omarchy kernel 7.2.15, Intel Xeon E5-2680 v3 @2.50GHz, 24 логических CPU, 15,5 GiB RAM; машина используется совместно с другими процессами. Host Node 26.12.0/npm 12.2.1. Electron 45.3.2: встроенный Node 24.22.2, ABI 150, N-API 10. Native better-sqlite3 13.2.0 поставляет prebuilds через Node-API; проверен реальный запуск в Electron, а не предположение о совпадении host ABI.

```sh
npm ci
npm run typecheck
npm test
npm run test:e2e
npm run benchmark
npm run pack:linux
npm run test:pack
```

TypeScript strict — без ошибок. Vitest — **98/98**. Проверка упакованного Linux-приложения прошла отдельно: проверен список ASAR, development=false, доверенных ключей 0, приватных файлов нет, публичный тестовый токен отклонён. Настоящий бинарник перезагрузил интерфейс с сетевым offline-режимом и вычислил Ø30, загрузив локальный Worker и SQLite prebuild вне ASAR. Отчёт: `test-results/packaged-report.json`.

Основной E2E-набор — **4/4** (см. актуальное повторение и артефакты в test-results). При изменении исходников E2E сначала пересобирает development-клиент; проверка пакета запускается отдельно после release-упаковки.

Модульные проверки: G90/G91/G54, диаметр → радиус, исходное T0101, 100 мм/F100 = 60 с, все направления/плоскости дуг с центром/R, полная окружность, неверные радиусы, неподдерживаемые команды/числа/лимиты, атомарность. Шесть практических примеров проверены по размерам. Объёмы точения и торцевания сравниваются с аналитическими кольцами/цилиндром; фрезерный проход — с прямоугольником и капсулой. Проверены канавка, тело инструмента, губки, патрон, G0 в материале, отсутствие инструмента/шпинделя, неверное вращение, пределы осей, длинный проход через препятствие, возврат материала и модального состояния. Неверный G54 меняет обработку относительно неподвижной заготовки. Незавершённое выполнение не получает проходную оценку даже при совпавших размерах.

Лицензии: замены payload/подписи, productId/keyId/kind/version, неизвестные/повторяющиеся модули, даты на границах, привязка, повторные и escaped JSON-ключи, глубина/размер/повреждение, защищённый PKCS#8, публичный вектор. Проверены owner CLI-команды keygen → issue Teacher на 365 суток → verify. Отдельно интерактивно проверены keygen --encrypt → issue с вводом пароля без эха → verify.

E2E настоящего Electron (Playwright `_electron`, renderer sandbox включён):

- Урок → разбор → отметка → контроль 6/6 → закрытие → восстановленный профиль/прогресс/попытка.
- Обе обработки из UI, Ø30 и глубина 3; импорт файла `.fcnclic`, отказ изменённой подписи с сохранением активной лицензии, разрешённое задание, сохранение проекта, светлая тема.
- Ввод программы с клавиатуры в Monaco, авария и синтаксическая ошибка, 2D, сброс Ø30 → Ø40 и следующий кадр, отказ модулю milling у лицензии без него, проверка IPC-схем.
- Резервная копия живой WAL-БД → quick_check → запуск приложения на отдельной восстановленной копии. Миграция отдельной БД v0 → v1 сохраняет контрольную запись и создаёт before-migration backup.
- Истёкшая лицензия блокирует новое лицензируемое действие, сохраняя экспорт JSON. Проверка большого отката часов включена в validation-сценарий.

Визуально просмотрены тёмная главная, редактор/материал обоих станков, светлая тема, ошибка, авария и узкий экран. Скриншоты сохраняются в test-results. Размеры viewport: 1366×768, 1093×614 и 911×512; нет горизонтального overflow, на узком экране переключаются вкладки. Последние два размера моделируют доступную площадь при увеличении масштаба, но **не заменяют** реальную проверку Windows DPI. Проверены доступные названия свёрнутого меню и клавиатурный ввод; полной сертификации доступности нет.

Benchmark: `docs/benchmarks/linux-x64.json`, 3 измерения после прогрева. На зафиксированном запуске траектория ≈0,45/0,38 мс; материал ≈5,18/31,71 мс (точение/фрезерование). Сетки 80×240 и 240×160 при 0,25 мм. Объёмы 16493,3614 и 1800 мм³; ошибка относительно этих простых аналитических примеров <1e-9 и 0 мм³. Максимальный RSS процесса benchmark ≈132,5 MiB; это не измерение полной памяти Electron/Three.js и не гарантия FPS.

Предупреждение Vite о JS chunk >500 kB остаётся: Monaco/Three поставляются локально одним основным bundle. Сборка завершается успешно. Разделение bundle и длительный тест памяти — последующая оптимизация, не скрытая ошибка проверки.

Windows CI подготовлен, но **не запускался из этой среды**. Не проверены Windows installer/portable, кодовая подпись, чистая установка, обновление, удаление, кириллический путь самого установщика, Windows 125–150%, конкретные учебные GPU. Не проверены отсутствующие сервер/CAD/CAM/преподаватель/полные экзамены; для них нет фиктивно проходящих тестов. Полный продукт не принят.

Omarchy: локальный пакет `firecnc-academy 0.1.0-1` собран makepkg и установлен pacman. Проверены desktop-file-validate, состав без файлов ключей, запись лаунчера в Gio и `pacman -Qk` (177 файлов, отсутствующих нет). Через установленную команду выполнен автономный пример Ø30 в отдельном временном профиле, подтверждены sandbox/contextIsolation. Затем приложение запущено обычным desktop-ярлыком; Hyprland подтвердил класс `firecnc-academy` и нативное Wayland-окно (xwayland=false). Исходный проект для запуска установленного приложения и системный Node.js не требуются.

Обновление Omarchy 0.1.0-2: в release включён открытый ключ владельца. Проверены импорт настоящего `issued/teacher.fcnclic` в отдельном профиле, статус Teacher, разрешение собственной токарной программы и отказ повреждённой подписи с сохранением действующей лицензии. Перед обновлением выполнен SQLite backup; после него проверены сохранение ID установки и числа учебных записей. ASAR установленного пакета совпадает с проверенной сборкой. Приватный ключ в клиент не добавлялся.

Версия 0.2.0: 17 дополнительных проверок GitHub Releases (версии, неизвестный/повреждённый/слишком большой ответ, offline, параллельные запросы, расписание и выключатель). Electron E2E показывает новый выпуск, проверяет безопасную ссылку и сохранение настройки после перезапуска. Удалённые Windows/Linux build и installer-проверки выполняются workflow Desktop builds and releases; их фактический статус виден в GitHub Actions.
