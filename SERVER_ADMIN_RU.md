# Сервер активации FireCNC

Отдельный один экземпляр Fastify 5.12.8 + SQLite, Node 24 LTS. Клиент и офлайн-лицензия работают без него. Lab означает число установок; плавающего сетевого lease-протокола нет.

## Локальная проверка

```sh
npm ci
npm run license:dev
npm run server:setup -- --key .local/issuer-private.pem
npm run server:start
```

Сервер слушает только `http://127.0.0.1:3679`. Конфигурация `.local/activation/config.json` создаётся один раз с правами 0600: путь к закрытому ключу, SQLite, случайный административный токен, порт, leaseSeconds и proxy. Существующие файлы не перезаписываются. Development-клиент (`npm run dev`) доверяет соответствующему открытому ключу. Production использует отдельный ключ владельца: `--key private-keys/issuer-private.pem` и сборка с его **публичным** trusted-keys.json. Никогда не помещайте закрытый ключ в клиент.

В другом терминале:

```sh
npm run server:create -- --edition lab --seats 3 --days 365 --customer "Учебная лаборатория" --output .local/lab-key.json
npm run server:list
```

Короткий ключ находится в сохранённом JSON. В клиенте «Настройки и лицензия» → «Активация коротким ключом через сервер»: введите адрес и ключ. После проверки подписи доступны подтверждённые модули. Список модулей по умолчанию задаётся редакцией; `--modules theory,turning,...` задаёт явный набор. `npm run license:activation -- ...` — эквивалент выпуска короткого ключа.

Административные команды читают токен из защищённой конфигурации, не из аргумента и не из desktop:

```sh
npm run server:admin -- show --id UUID-ЛИЦЕНЗИИ
npm run server:admin -- limit --id UUID-ЛИЦЕНЗИИ --seats 5
npm run server:admin -- revoke --id UUID-ЛИЦЕНЗИИ
npm run server:admin -- reset --id UUID-АКТИВАЦИИ
npm run server:backup -- --output /защищённый/каталог/activation.sqlite
```

Подставьте реальные UUID из `server:list`. Резервную копию нельзя перезаписать этой командой. Для зашифрованного PKCS#8 сервер получает пароль через защищённую переменную `FCNC_SIGNING_PASSWORD`; не передавайте его аргументом и не храните в Git. Для выпуска ключей с интерактивным паролем используйте owner CLI `license:keygen -- --encrypt`.

## Семантика мест и времени

Ключ содержит 160 случайных бит (20 randomBytes → 32 Crockford Base32), префикс/дефисы не считаются энтропией. Нормализация общая: верхний регистр, удаление пробелов/дефисов, строгий алфавит без неоднозначных O/I/L/U. Сервер хранит SHA-256 с разделением назначения, исходный ключ показывается только при выпуске.

Клиент создаёт отдельный случайный 256-битный секрет установки при активации и сохраняет его **до** запроса. Это позволяет безопасно повторить запрос после потери ответа; сервер хранит только хеш. Публичного installationId недостаточно для renew/deactivate. ID — случайный устойчивый идентификатор приложения, не HWID.

Проверка лимита и запись места выполняются одной SQLite BEGIN IMMEDIATE-транзакцией. Та же установка с тем же секретом не занимает дополнительного места. Потеря служебного секрета требует сброса владельцем. Серверный lease подписывается Ed25519, привязан к хешу установки, действует максимум 7 суток и не дольше основной лицензии. Клиент повторяет продление при запуске/раз в 6 часов, когда до срока осталось меньше двух суток.

Отзыв прекращает активацию/продление. Ранее выданный lease продолжает действовать до expiresAt. **Даже deactivate/reset удерживает место до конца ранее выданного lease**; API возвращает reservedUntil. Это исключает выдачу лишних одновременных автономных мест. Снизить лимит ниже уже зарезервированного числа нельзя. Деактивированный клиент сразу перестаёт использовать свой lease; его проекты/результаты сохраняются. Недоступность сервера не отменяет действующее разрешение. Локального обхода срока нет.

## Развёртывание и восстановление

Оставьте Node-сервер на localhost и поставьте перед ним свой HTTPS reverse proxy. Desktop допускает HTTP только для loopback, во всех остальных случаях требует HTTPS и запрещает redirect. Включайте `proxy: true` только за доверенным локальным proxy: доверяются loopback-адреса, а не произвольный X-Forwarded-For.

Административный API — Bearer с отдельным случайным токеном. Доступ к `/admin/` ограничьте сетью владельца на proxy. Тела ограничены 16 KB, схемы строгие, дубликаты JSON отвергаются, запросы ограничиваются по IP; приватные ответы имеют Cache-Control no-store. Сервер не пишет тела/токены в HTTP-лог. `/health` не раскрывает клиентов. Административный журнал хранит последние 10000 действий.

SQLite Backup API копирует согласованный снимок с учётом WAL. Закрытый ключ и конфигурацию с административным токеном резервируйте **отдельно**, с шифрованием и ограниченным доступом. Для восстановления остановите единственный экземпляр, сохраните текущую БД/ключи, восстановите согласованную БД и именно тот ключ подписи, проверьте права и `/health`, затем проверьте известную активацию. Смена ключа требует заблаговременного добавления нового открытого ключа в клиентские сборки. Копирование одного живого .sqlite без WAL не является резервным копированием.

API: POST `/v1/activate`, `/v1/renew`, `/v1/deactivate`; GET `/health`; POST/GET `/admin/licenses`; GET/PATCH `/admin/licenses/:id`; POST `/admin/activations/:id/reset`. Схемы — services/activation-server/src/server.ts. Транзакции и конкуренция проверяются настоящими параллельными HTTP-запросами в Vitest.
