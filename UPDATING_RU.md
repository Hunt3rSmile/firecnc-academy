# Выпуски и проверка обновлений

Публичный репозиторий и загрузки: https://github.com/Hunt3rSmile/firecnc-academy/releases

Установленное приложение проверяет GitHub через 10 секунд после запуска, затем каждые 6 часов. Настройки → «Обновления приложения» позволяют проверить вручную и отключить фоновые запросы. В development автоматических запросов нет. Показанный номер сравнивается по SemVer; черновики, prerelease и более старые версии не предлагаются.

Обновление открывает страницу конкретного выпуска только на `github.com/Hunt3rSmile/firecnc-academy/releases/tag/...`. Ответ API ограничен 1 MiB и 12 секундами ожидания; параллельные запросы объединяются. В запросе нет профиля, installationId, лицензии, программы или ответов студента. Отсутствие сети не мешает обучению и действующей офлайн-лицензии.

Приложение **сообщает** о выпуске. Пользователь скачивает нужный файл и устанавливает его. Загрузка и исполнение неподписанного обновления внутри приложения не добавлены. Windows-сертификат владельца не настроен; Authenticode-подпись не заявляется. У Omarchy версия управляется pacman; бинарные файлы в `/opt` приложение самостоятельно не заменяет.

Данные находятся в каталоге Electron userData (`FireCNC Academy`), отдельно от установщика. При обновлении используйте тот же каталог данных. Сохраните открытый проект; для резервирования есть SQLite Backup API в настройках. Лицензия сохраняется при обычной замене приложения, если новый выпуск доверяет тому же ключу подписи.

## Как выпустить следующую версию владельцу

1. Внесите изменения, выполните `npm run typecheck`, `npm test`, `npm run test:e2e`.
2. Поднимите версию: `npm version patch --no-git-tag-version` (либо minor).
3. Добавьте заметки `docs/releases/vX.Y.Z.md`, обновите версию PKGBUILD для пакета Arch.
4. Закоммитьте исходники и lock-файл, отправьте main. Запустите `gh workflow run desktop.yml --ref main -f publish=true` либо создайте и отправьте тег `vX.Y.Z`. Workflow-dispatch позволяет создать тег только после успешных сборок.
5. Workflow **Desktop builds and releases** проверит проект, соберёт Windows и Linux, проведёт пакетные проверки, запуск portable/AppImage и NSIS-переустановку и создаст Release только после успешных заданий обеих платформ.
6. После публикации новые клиенты предложат этот выпуск при следующей проверке. Первое обновление с 0.1, где проверки ещё не было, нужно установить вручную.

Публичный ключ владельца хранится в `config/trusted-keys.json` и встраивается при сборке. Закрытый ключ остаётся только у владельца. Для CI он не нужен: сборка ничего не подписывает как лицензию. Не удаляйте действующий публичный ключ при обычном обновлении; ротация описана в LICENSING_ADMIN_RU.md.

GitHub API для публичных выпусков работает без токена. Секрет GitHub не включается в клиент. Если сделать репозиторий закрытым, эта схема проверки без входа перестанет работать; потребуется отдельный публичный канал загрузок.

Источники: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases), [SemVer](https://github.com/npm/node-semver), [Electron security](https://www.electronjs.org/docs/latest/tutorial/security).
